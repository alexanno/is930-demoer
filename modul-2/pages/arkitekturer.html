Arkitekturer

Arkitektur handler om hvordan data, server og klient settes sammen. Samme kart kan bygges på mange måter, med store forskjeller i kostnad, drift, sikkerhet og fleksibilitet. Her er fire vanlige mønstre, bygget av verktøyene fra de foregående temaene. Hovedregelen er å velge det enkleste mønsteret som løser oppgaven.

1. Frontend-only

Nettleser
HTML og JavaScript		→Andres tjenester
Kartverket, Geonorge, OpenStreetMap

Figur: Variant a: appen bruker andres tjenester

Nettleser
HTML og JavaScript		→Egne filer på statisk lagring
PMTiles, COG, GeoParquet

Figur: Variant b: cloud native, egne filer leses direkte

Appen har ingen egen server. I variant a er backend «andres problem»: nettleseren spør tjenester som Kartverket, Geonorge og OpenStreetMap, som selv har kartserver og database bak seg. Appen din er altså en klient i andres 3-lags arkitektur. Demoappen viser hvor mye du får til med én HTML-fil: bakgrunnskart som kartfliser, et WMS-lag, og oppslag på stedsnavn, kommune og høyde. Variant b er cloud native: du legger egne filer (PMTiles, COG eller GeoParquet) på statisk lagring og leser dem direkte, slik beskrevet i Databaser og lagring.

Pris du betaler: alt er offentlig, så nøkler i koden kan leses av alle. I variant a er du avhengig av at andre holder tjenestene oppe og beholder vilkårene sine. Bruk for eksempel OpenStreetMaps flisregler og lisensen til hvert lag.

2. Frontend + backend-API + PostGIS

Nettleser→API
Node, Python eller edge function		→PostGIS
database med geodata

Figur: backend mellom nettleser og database

Når dataene ligger i en database, må noe stå imellom: et API som tar imot forespørsler, spør PostGIS og returnerer for eksempel GeoJSON. Nettleseren får aldri databasepassordet. postgis-sql-api er et lite eksempel på dette, og Supabase-oppgaven fra IS-218 viser det samme som en «edge function».

GET /api/sqlapi?sql=select navn from skole order by geom <-> 'SRID=4326;POINT(8.0 58.15)' limit 3

Dette eksempelet sender fri SQL fra nettleseren og er kun egnet i undervisning, med en databasebruker som bare kan lese. I virkelige løsninger lager du faste endepunkter, for eksempel /skoler?kommune=4204, eller bruker ferdige verktøy som pg_featureserv eller Supabase.

3. 3-lags med kartserver

Klient
nettleser, QGIS, andre systemer		→Kartserver
GeoServer, MapServer, pygeoapi		→Database eller filer
PostGIS, GeoPackage

Figur: presentasjon, logikk og data i hver sin del

Klient, tjeneste og data er hvert sitt lag. Ved å publisere data som standardtjenester (WMS, WFS, OGC API, se API-standarder) kan mange ulike klienter bruke samme tjeneste: nettleseren, QGIS og andre systemer. Slik er de nasjonale tjenestene på Geonorge bygget. Kostnaden er at du selv må drifte, oppdatere og sikre serveren. Programvaren står i Desktop, web og serverprogramvare.

4. Caching og tile-pyramider

Nettleser→Cache eller CDN
MapProxy, nettleser-cache		→Kartserver eller fliser

Figur: cache foran tjenesten

Ved å lage ferdige fliser for alle zoomnivåer (en pyramide) og legge dem i en cache eller et CDN slipper serveren å tegne kartet på nytt for hver bruker. Resultatet er raskt og billig, men fungerer best når dataene sjelden endres. PMTiles er en hel flispyramide i én fil. Oppdateringer betyr at fliser må lages om og cachen tømmes. Dette mønsteret legges som regel til oppå mønster 2 eller 3.

Velg arkitektur

Spørsmål Peker mot
Er dataene åpne, og endres de sjelden?Frontend-only (eventuelt cloud native)
Må noen kunne endre data, eller må noe holdes hemmelig?Frontend + backend-API
Skal mange ulike systemer bruke tjenesten din?3-lags med standardtjenester
Mange brukere eller tunge kart?Legg til caching

Mønstrene kan kombineres, for eksempel frontend + API + PostGIS bak, med cache foran.

Aktivitet

Forslag til øvelser du kan prøve på egenhånd:

  • Åpne demoappen, bytt bakgrunn, slå på naturvern og klikk i kartet. Åpne nettleserens utviklerverktøy (fanen Network). Hvor mange ulike tjenester snakker appen med, og hvem drifter dem?
  • Hva skjer med en frontend-only-app hvis en av tjenestene den bruker går ned eller endrer vilkår? Hva kan du gjøre for å redusere risikoen?
  • Tegn arkitekturen for en case fra din virksomhet, for eksempel «kunder på kart». Hvilket mønster velger du, og hvorfor ikke de andre?
  • Be en KI-agent legge et nytt WMS-lag fra Geonorge kartkatalog til demoappen. Hva måtte endres?
